# 日常实验

Main 是新的主工程目录。Windows 编辑与 WSL 编译使用同一份源码。每个终端先进入一次受限 Shell，随后按讲义执行 cd、make、make run、make menuconfig 和 make gdb。

## 进入实验终端

在 Windows PowerShell 5.1 或 PowerShell 7 中，从 Workspace 根目录执行：

```powershell
Set-Location E:\Workspace
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Shell
```

已经打开普通 WSL Ubuntu 终端时执行：

```bash
bash /mnt/e/Workspace/Tools/wsl-sandbox/run.sh shell
```

进入后默认位于 Main，NEMU_HOME、AM_HOME、NPC_HOME、NVBOARD_HOME 和 Verilator 的 PATH 均已设置。提示符中包含 @ysyx。之后的实验命令直接输入，无需每次包装 make。

## 编辑、构建与运行

在 Windows 编辑器中打开 E:\Workspace\YSYX\Main。保存后，在已进入的受限终端运行：

```bash
cd nemu
make
make run
```

看到 (nemu) 后输入 NEMU 自己的命令，例如 help 查看帮助、c 执行、q 退出。框架已提供的内置镜像可执行 4 条指令并得到 GOOD TRAP；其他功能按课程逐步实现。

配置和调试也使用原命令：

```bash
make menuconfig
make gdb
```

配置菜单使用方向键和回车，Esc、Esc 退出。当前默认 NEMU 构建没有源码调试信息；如需 GDB 按源码行单步，在 menuconfig 的 Build Options 中开启 Debug information 后重新 make。现有构建已验证 GDB 函数断点可用。

Ctrl+C 中止当前前台程序并回到 Shell，exit 退出整个受限终端。不要在普通 WSL 终端绕过入口直接运行项目程序。

## 图形与依赖下载

需要 NVBoard 或 GTKWave 时，在进入时增加图形选项：

```powershell
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Shell -Gui
```

WSL 的等价入口：

```bash
bash /mnt/e/Workspace/Tools/wsl-sandbox/run.sh shell --gui
```

进入后运行官方 NVBoard 示例：

```bash
cd nvboard/example
make run
```

退出图形示例使用窗口关闭操作或 Ctrl+C。显示使用 WSLg X11 和软件渲染，程序仍受项目资源限制。

普通实验默认不联网。确需初始化新的公开依赖时，以 -Network 或 shell --network 进入；按讲义运行 bash init.sh。沙箱专用 Git HOME 将 GitHub SSH 地址重写为 HTTPS，不依赖宿主 SSH 密钥。APT 系统包安装仍走 [环境工具](../../tools/README.md) 的专用入口。

## Git 与换行

日常 Git 操作在 Windows 的 Main 目录执行，官方 Makefile 的 tracer-ysyx 自动追踪在隔离构建中继续运行。远程按讲义的分工配置：origin 是个人备份仓，upstream 是 OSCPU/ysyx-workbench 官方来源。手工提交用 `git commit --allow-empty`，`git log --author` 用于筛出自己的提交；推送备份就是从这个目录执行 `git push origin master`，tracer-ysyx 分支同时保留在个人仓。不要删除 tracer-ysyx 分支，也不要改写或清除跟踪历史。

主工程文本使用 UTF-8、LF。Main/.gitattributes 管理 Git 检出与提交规范，.editorconfig 设置支持 EditorConfig 的编辑器默认值；以 Main 为工作区打开 VS Code 时，.vscode/settings.json 设置新文本文件为 UTF-8、LF。编辑器仍可手动覆盖已有文件的换行，应查看状态栏的 LF 标记。

二进制文件不做换行转换。独立第三方仓库使用自己的 Git 配置；Capstone 的 Windows/VB6 绑定等文件保留其上游 CRLF，当前 Linux 构建源不依赖这些文件。

## 限额、日志与重启

每个受限会话最多 30 分钟，包括在提示符等待的时间；到期后使用同一个入口重新进入。源码与构建文件保存在项目卷中，不因会话结束消失。内存 3 GiB、合计 2 CPU 时间、进程数、单文件和全卷容量限制继续生效。

交互输出实时显示，会话退出后生成 YSYX/logs/ 下的 JSON，仅登记命令、选项、退出状态和限制，不自动录制终端输入输出。NEMU 自身日志仍位于 nemu/build/。Run 模式与 first-run.py 用于自动安装检查，另存 stdout、stderr 和 JSON，日常不要求重复执行。

Windows 重启后，卷在 WSL 内由系统挂载单元随启动恢复，不需要每次手工挂载。只有在 Windows 侧提示虚拟磁盘未连接时，才从 Workspace 根执行：

```powershell
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Mount
```

随后按上文重新进入 Shell。挂载点、VHDX、profile、state、沙箱 HOME 都是环境组成部分，不按普通缓存删除。完整适配、首次运行和本轮核对结果见 [开发环境](开发环境.md)。
