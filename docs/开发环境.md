# 开发环境与首次运行

记录日期：2026-10-13。本轮从官方初始代码建立新的 Main 主工程，使用 WSL Ubuntu 进行受限构建与运行。

## 来源与初始化

主仓来自 [OSCPU/ysyx-workbench](https://github.com/OSCPU/ysyx-workbench) 的 master 分支，基线为 c35eee8。依据 [YSYX 2607 E3](https://ysyx.oscc.cc/docs/2607/e/3.html)、[E4](https://ysyx.oscc.cc/docs/2607/e/4.html) 和 [PA0](https://ysyx.oscc.cc/docs/ics-pa/0.6.html)；离线资料位于仓外的 YSYX/docs/。

| 内容 | 上游分支或版本 | 初始化方式 |
| --- | --- | --- |
| NEMU | NJU-ProjectN/nemu，ics2024 | 源码纳入主仓，初始化提交 1c3cd02 |
| Abstract Machine | NJU-ProjectN/abstract-machine，ics2026 | 源码纳入主仓，初始化提交 f5ac33e |
| fceux-am | ics2021 | 独立依赖仓，主仓忽略 |
| NVBoard | master | 独立依赖仓，主仓忽略 |
| Capstone | 5.0.6 | 位于 nemu/tools/capstone/repo，主仓忽略 |
| Verilator | stable，5.052 | 源码放在 YSYX/cache/verilator-src，安装到 YSYX/tools/verilator-5.052 |

完整 URL、分支与源提交集中登记在 [sources.json](sources.json)。子项目分支严格采用本次主仓 init.sh 的配置；没有从 raw/ 复制代码或构建产物。

初始化使用 Windows Git 和 HTTPS，按上游 init.sh 的方式把 NEMU、AM 源码并入主仓，其他依赖保持独立。保留上游 Makefile 的 tracer-ysyx 自动跟踪逻辑；学号和姓名仍为官方占位值，正式登记后再修改。

## 系统与依赖

实际环境为 WSL 2、Ubuntu 26.04 LTS，GCC/G++ 15.2、Python 3.14.3、GNU Make、GDB 17.1。沿用该发行版原有 resolute 软件源，没有换成讲义示例中的旧 Ubuntu 源。

[PA0 安装说明](https://ysyx.oscc.cc/docs/ics-pa/0.3.html) 要求基础构建工具、man、GCC 文档、GDB、Git、readline、SDL2。[Verilator 安装说明](https://verilator.org/guide/latest/install.html) 和 [NVBoard README](https://github.com/NJU-ProjectN/nvboard) 补充了构建与图形库要求。

| 用途 | 依赖 |
| --- | --- |
| 基础开发与文档 | build-essential、man-db、gcc-doc、gdb、git、perl、python3、pkg-config |
| NEMU 与 Kconfig | libreadline-dev、libncurses-dev、flex、bison |
| Verilator 源码构建 | autoconf、automake、libtool、help2man、ccache、libfl-dev、zlib1g-dev、liblz4-dev |
| 虚拟板卡与波形 | libsdl2-dev、libsdl2-image-dev、libsdl2-ttf-dev、gtkwave |

APT 实际结果为 0 个升级、33 个新增、0 个移除。部分包原先已装；33 个新增包含传递依赖。精确版本与安装差异以 [安装前清单](../../logs/dependencies/before.tsv)、[安装后清单](../../logs/dependencies/after.tsv) 和 [APT 原始输出](../../logs/dependencies-install.log) 为准。

系统自带的 Verilator 为 5.032。按照讲义从官方 stable 构建 5.052，使用项目内前缀，不覆盖系统工具。构建脚本为 [build-verilator.sh](../../tools/build-verilator.sh)，源版本登记后固定在脚本中；更换版本时需同步源码登记、安装前缀与 profile PATH。

系统包安装需要写 /usr、/var 等系统目录，使用 WSL root 执行 APT；这是包管理例外。工具源码编译、NEMU 构建、仿真及示例执行仍使用普通账号通过隔离入口运行。

## WSL 适配与修改

| 发现的问题 | 本轮处理 | 作用范围 |
| --- | --- | --- |
| 隔离入口仍默认旧工程名称 | profile 的 workbenchDirectory 改为 Main；cwd 与 NEMU_HOME、AM_HOME、NPC_HOME、NVBOARD_HOME 统一生成 | YSYX profile；通用入口保留默认旧名称供未配置的其他 profile 使用 |
| 旧工程全局编译覆盖会影响新框架 | 清除 CFLAGS=-ffreestanding 与全局 CROSS_COMPILE 覆盖，仅保留串行 make | 新 Main；没有改工具链名称或系统默认编译器 |
| Windows 子项目检出为 CRLF | 新下载的子仓设置 core.autocrlf=false、core.eol=lf，再从索引检出；Main 增加 .gitattributes | 新工程源码，不更改 raw/ |
| Linux 显示目录可写但 mkdir 仍被拒绝 | 为当前 Windows 账号在 Main 根及新工具安装目录添加可继承 FullControl，使用 icacls；保存 Main 的 [原 ACL](../../logs/main-acl-before.sddl)、[修复后 ACL](../../logs/main-acl-after.sddl)，以及工具目录的 [原 ACL](../../logs/verilator-install-acl-before.sddl)、[修复后 ACL](../../logs/verilator-install-acl-after.sddl) | 仅 Main 与 tools/verilator-5.052；未修改整个 Workspace 或放宽沙箱挂载 |
| 沙箱外普通 /mnt/e 路径读取虚拟卷报 I/O 错误 | 系统包脚本从 /mnt/wsl-sandbox/ysyx 读取；沙箱内仍映射为 /mnt/e/Workspace/YSYX | 路径使用约定，无第二份源码 |
| 沙箱 HOME 与宿主环境隔离 | 在沙箱专用 home/.gitconfig 配置提交身份，构建变量由 profile 注入 | 不修改宿主 ~/.bashrc 或宿主 Git 身份 |
| 入口没有交互终端 | 用官方 Kconfig conf --alldefconfig 和 --syncconfig 生成默认配置；首次运行通过子进程标准输入发送 help、c、q | 默认配置等同于菜单保持默认；没有默认改变 ISA 或关闭 trace |
| Verilator 生成版本时在 DrvFs 全仓扫描较慢 | 使用上游支持的 VERILATOR_SRC_VERSION，值来自已登记版本；构建前显式重新生成版本头 | 只影响工具版本字符串生成，不修改 RTL 或编译器源码 |
| 旧 difftest 绝对路径不适用于新框架 | 新 profile 不挂载 /home/normal/ysyx-workbench；需要兼容时须显式配置 legacyDifftestPath | 新 Main 环境 |

上述构建依赖本身是常规 Linux 包；本轮 WSL 特有处理主要是卷路径、Windows ACL、换行符和隔离环境变量。现有 Bubblewrap、systemd/cgroup 与 WSLg 沿用已搭建环境。

资源限制保持为项目总内存 3 GiB、2 CPU 时间、256 个任务、零 swap、每次运行 30 分钟、每任务临时盘 256 MiB、单文件 2 GiB，以及全卷 12 GiB。挂载或限额校验失败时入口拒绝运行。

Verilator 版本扫描首次中断后遗留空版本头，曾触发 DTVERSION_rev 未定义；构建脚本现显式调用上游生成器重新生成版本头，并在构建前比较当前 Git 提交与来源登记，防止源版本改变后仍显示旧版本标记。

汇总、各组件实际判据、产物一次身份登记和安装复制比较见 [main-first-run.json](../../logs/main-first-run.json)。已比较安装前后的 Verilator 发布版二进制，SHA-256 一致；此项只验证该复制边界。NEMU、Capstone、两个示例程序的摘要用于身份登记，功能结果以相应运行记录为准。

## 复现入口

从 Workspace 根目录执行：

```powershell
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Doctor
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Run -Command @('python3', '-B', 'tools/first-run.py')
```

只运行 NEMU：

```powershell
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Run -Command @('python3', '-B', 'tools/first-run.py', '--component', 'nemu')
```


NVBoard 的限时图形启动检查：

```powershell
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Run -Gui -Command @('python3', '-B', 'tools/nvboard-startup.py')
```
WSL 终端中的同一入口：

```bash
bash /mnt/e/Workspace/Tools/wsl-sandbox/run.sh python3 -B tools/first-run.py
```

入口自动保存 stdout、stderr 和 JSON 到 YSYX/logs/。有保留价值的来源、验证与产物身份应复用已有登记；普通日常复跑无需额外重算摘要。
